# projects/ — Execution Hub Layer

Execution hub layer. The management unit for initiatives that bundle multiple tasks.

## Directory Naming

`projects/{slug}/` (kebab-case). Each project is **one directory containing one main file (`_project.md`)**.

## Required Files

```
projects/{slug}/
├── _project.md             # required: meta + state + body
├── _summary.md             # optional, at completion
└── NNN-description.md      # optional artifacts
```

## State (`status` values)

- `planning`: scope being shaped
- `active`: tasks in progress
- `paused`: temporarily paused
- `done`: completed

See `.claude/rules/rill-projects.md` for details.

## Completion Criteria (DoD) Required

Every project writes a verifiable completion condition in the Goal section (ADR-080).

## Relationship with Tasks (1:N via mention)

Tasks physically live under `tasks/`, linked to projects virtually via `mentions: [projects/{id}]`. The `Active Tasks` section in `_project.md` is auto-generated by mention reverse-lookup.

## Creating New

```bash
rill mkfile projects --slug {id} --type project \
  --field 'name=...' \
  --field 'description=...'
```

Both `--field 'name=...'` (~30-60 chars descriptive title) and
`--field 'description=...'` (1-3 sentence summary) are required —
`rill mkfile` rejects calls missing either.

For interactive creation use `/project new` (it asks for name,
description, Goal, status). For workspace crystallisation use
`/promote`, which seeds the inputs from `_summary.md`.
