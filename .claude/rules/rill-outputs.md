# Output Rules — Rill

`reports/` and `pages/` are the **output layer** — Claude Code-generated artifacts and human-facing aggregated documents.

## reports/

```
reports/
├── daily/         # Daily Note (/briefing)
├── newsletter/    # Research reports (/newsletter)
├── eval/          # Metadata quality reports (/eval)
├── distill/       # Tier 1 Key Fact curation reviews (/distill)
└── retrospective/ # Weekly retrospectives (/retrospective)
```

### reports/daily/

`YYYY-MM-DD.md`. Daily Note from `/briefing`. Integrates forward-looking (today's focus) + backward-looking (yesterday's activity), prose-quality. Tasks collected from `type: task` tickets with context-rich summaries (ADR-063).

```yaml
---
created: 2026-03-11T08:00+09:00
type: daily-note
date: 2026-03-11
journal-count: 3
---
```

### reports/newsletter/

`YYYY-MM-DD.md`. From `/newsletter` (ADR-031). 3-layer context model (Identity/Attention/Impulse). Alerts limited to past 2 weeks.

### reports/eval/

Metadata quality reports from `/eval`. Not to be confused with `eval/` (structured metrics data; `reports/eval/` is the human-readable report). Two layouts:

- **Flat**: `reports/eval/{YYYY-MM-DD}.md` — default one-file report
- **Harness directory**: `reports/eval/{slug}/` — multi-file session with runners, fixtures, outputs co-located. `*.md` at root = canonical reports; subdirs (`fixtures/`, `outputs/`) hold harness assets and are not surfaced in Reports View

### reports/distill/

`tier1-curation-{YYYY-MM-DD}.md`. Tier 1 Key Fact curation review, generated by `/distill` Step 7.5 (conditional — only when a Tier 1 entity crosses the curation-due threshold). Lists deletion/merge candidates per flagged entity for human `[x]` approval. Generated via `rill mkfile reports/distill --type distill-curation` then renamed to the slugged filename (the generic `reports/*` mkfile branch ignores `--slug` and always writes `{YYYY-MM-DD}.md` — same rename pattern as `reports/retrospective/` below).

```yaml
---
created: 2026-06-01T10:00+09:00
type: distill-curation
period: 2026-06-01
---
```

### reports/retrospective/

`weekly-{YYYY-MM-DD}.md` (the Monday of the covered ISO week). From `/retrospective`. 5 sections (Cross-WS Themes / Contradictions / Stale Workspaces / Decision Digest / Self Observations). Generated via `rill mkfile reports/retrospective --type retrospective` then renamed to the canonical `weekly-{period}` filename, preserving `created` across `--rerun`.

```yaml
---
created: 2026-05-04T09:00+09:00
type: retrospective
period: weekly-2026-05-04
---
```

`reports/` are searchable (ADR-061) — `/focus` context collection and `/briefing` Grep them. But reports/ content is **not auto-distilled** to knowledge/notes/.

## pages/

Flat directory (`pages/{id}.md`). Each page has a **recipe pair** (`{id}.recipe.md`).

- **Human-facing aggregated documents** (Materialized Views, wiki metaphor, ADR-062)
- **Excluded from AI search** (`/distill`, `/briefing`, `/eval` do not Grep pages/)
- Direct edits should first fix canonical sources (inbox/, knowledge/), then reflect in pages (D62-5)

### Frontmatter

```yaml
---
created: 2026-03-24T10:00+09:00
type: page
id: body-recomposition
name: Body Recomposition Strategy
description: Aggregation of training strategy, dietary guidelines, and weekly log
updated: 2026-03-24T08:00+09:00
tags: [fitness]
sources:                           # optional
  - knowledge/notes/body-recomp-basics.md
---
```

Required: `created`, `type: page`, `id`, `name`, `description`. `id` matches filename (kebab-case, no date prefix).

### Recipe File (required)

`{id}.recipe.md` describes purpose, source hints, fixed sections. `type: recipe`. Structure not prescribed — AI judges from purpose.

### Updating pages/

**Read the corresponding `.recipe.md` first.** Recipes describe purpose and source hints, not rigid structures (ADR-062).

CRUD via `/page` skill. When editing directly, fix canonical source first then reflect. Generate via `rill mkfile pages --slug {id} --type page`.

### Writing Style

Prose-based. Tables only for comparisons. Maintain a chronological axis.
